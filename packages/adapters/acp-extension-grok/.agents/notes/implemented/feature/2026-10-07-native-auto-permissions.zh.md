# 在 Grok 1.0.46 恢复原生 Auto

Status: implemented
Translation: current

[English](2026-10-07-native-auto-permissions.md)

## 摘要

此前在修复 YOLO 权限弹窗时移除了 Auto；旧接入没有可靠的运行时确认，也没有完成
认证回合验证。本次固定官方 Grok 1.0.46，通过原生启动标志和客户端范围通知恢复
Auto，并设置独立的已验证版本门槛。官方二进制通过了使用本地合成模型接口的隔离
探针，验证了实际模式、分类和工具执行。协议仍无法确认 Auto 的有效状态，因此
选项明确表示请求的策略，Grok 功能开关关闭时仍可能按 Ask 执行。

## 决策与职责

本次部分替代[九月的兜底决策](../bug-fix/2026-09-09-yolo-permission-fallback.md)：
恢复 Auto，保留 YOLO 的适配器兜底、明确的 Plan 批准和已转发请求的宿主所有权，
实现 [Auto 草案](../../../../specs/auto-permissions.zh.md)。历史问题并未证实 Grok
Auto 分类器失效；宿主选择器只修改草稿、待批准历史导致弹窗，是另外的问题。

运行时固定为 1.0.46，基础兼容门槛保留 1.0.34，Auto 则要求运行时报告至少
1.0.46。旧版或未知版本在创建／fork 前拒绝 Auto，不伪造成功或静默恢复 Ask。
适配器升至 0.1.4，使权限能力缓存更新。依赖没有改变。

所有启动路径显式设置 `yoloMode` 和 `autoMode`，包括替换会话时继承的客户端
选择，以及明确的 false。运行时通知保留客户端标识。Auto 透传原生权限请求，
不会调用 YOLO 的允许选项兜底。标准 Plan／模型切换不改变请求的权限策略。
没有新增宿主 RPC、流、订阅或生产环境 hook。

Grok 设置通知只携带远程开关，不代表完整解析后的开关；会话信息也不包含有效
权限模式。两者都不能替代确认。因此适配器明确将 Auto 描述为请求，不复制原生
配置优先级，也不强制打开开关。这保留了可见的限制，没有虚构有效状态契约。
宿主静态目录、输入框提交行为和托管运行时发布仍需宿主集成，本仓库不修改它们。

## 验证

- 91 项确定性适配器／进程测试通过，语法构建和 typecheck 通过。
- `probe-auto-permissions.mjs` 使用生产入口与官方 macOS arm64 1.0.46
  （`grok 1.0.46 (2765805b9442)`），二进制 SHA-256 为
  `e8daa302364c9c3b6a5546d511cfbd1ab5e5d407a9b04282f660665ea405f9f3`。
- 本地 Chat Completions fixture 提供工具调用和分类器判定。无害的写重定向命令
  能触发分类器子查询；普通 Python 命令会被原生分类器的启发式预检查放行，不能
  只凭命令执行成功就宣布验证了模型分类路径。
- 探针通过仅供测试的原生 hook 事件观察实际模式，同时断言分类器调用、客户端
  权限请求和标记文件执行结果。覆盖 new、热／冷 load 和 resume、fork 后源会话
  继续使用、三种模式切换、分类器允许／阻止／不可用，以及开关关闭时启动和运行中
  选择 Auto 均回退到人工审批 Ask。
- 不使用真实凭据、用户历史、托管模型推理或产生账户费用。未验证托管分类器质量、
  其他平台或宿主 UI 集成。集成探针需显式运行，独立于离线确定性测试，通过协议
  完成信号推进，不使用 sleep。
- 本独立包没有父仓库 Lody 的 `docs status/check` 脚本，本机 pnpm 启动器也缺少
  缓存入口；使用本地 Markdown 链接检查和 diff 空白检查代替。
